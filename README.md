# 🎣 フィッシングゲーム - シーバスルアー釣り

ブラウザで遊べる3D釣りゲームです。キャストからファイト・キャッチまでの一連の流れを、
スマホのタッチ操作向けに実装しています。Three.js を使ったビルド不要の静的サイトで、
GitHub Pages でそのまま公開できます。

## 遊び方(ゲームの流れ)

1. **キャスト** — 「長押しでキャスト」ボタンを押すとパワーゲージが往復します。
   離した瞬間のパワーで飛距離(8〜34m)が決まります。
2. **リトリーブ(水中カメラ)** — 着水後は水中視点に切り替わります。
   「リール」ボタンの長押しで巻き、「トゥイッチ」で誘いを入れます。
   ドラッグで視点回転、ピンチでズーム。
3. **アタリ** — ルアーに興味を持った魚が追尾し、食いつくと画面に「アワセ!!」が表示されます
   (バイブレーション・効果音つき)。
4. **フッキング** — 表示中(約0.85秒)に画面をタップするとフッキング成功。遅れると逃げられます。
5. **ファイト** — テンションゲージを見ながらのやり取り。
   魚が走っている間に巻くとテンションが上がり、**ゲージが振り切れるとラインブレイク**。
   逆に緩めすぎるとフックが外れます。魚が止まったら巻いて距離を詰めましょう。
6. **リザルト** — 岸まで寄せればキャッチ! 魚種・サイズ・重さと自己記録
   (localStorage に保存)が表示されます。

## 攻略のヒント

- 魚は **1.0〜1.6 m/s 前後のリトリーブ速度** と強めのウォブリングに反応しやすい
- 追尾中の **トゥイッチ** や **ストップ&ゴー(巻きを止めた瞬間)** はバイト率が大きく上がる
- 大物(ランカーシーバス)ほど引きが強く、走っている間に巻くと一瞬でラインブレイクする
- 魚種はサイズで変化: セイゴ (〜39cm) / フッコ (40〜59cm) / スズキ (60〜79cm) / ランカーシーバス (80cm〜)

## 操作まとめ

| 操作 | 内容 |
|---|---|
| キャストボタン長押し → 離す | パワーを溜めてキャスト |
| リールボタン長押し | 巻き取り(リトリーブ / ファイト共通) |
| トゥイッチ | ダートアクションで誘う |
| アタリ中に画面タップ | アワセ(フッキング) |
| ドラッグ / ピンチ | 水中カメラの視点回転 / ズーム |
| ⚙ ボタン | リトリーブ速度・潜行レンジ・アクション強さ・ルアータイプの調整 |

PCでは Space(キャスト/リール/アワセ)と X(トゥイッチ)でも操作できます。

## ローカルで実行

ビルド不要です。`index.html` をそのままブラウザで開くか、簡易サーバーで配信します:

```bash
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

※ Three.js は CDN (jsdelivr) から読み込むため、インターネット接続が必要です。

## GitHub Pages で公開する

このリポジトリには GitHub Actions によるデプロイワークフロー
(`.github/workflows/deploy-pages.yml`)が含まれています。

1. このブランチを `main` にマージ(または push)する
2. リポジトリの **Settings → Pages** を開く
3. **Source** を **GitHub Actions** に設定する
4. `main` への push で自動的にデプロイされ、`https://<ユーザー名>.github.io/fishing/` で公開されます

(Actions を使わない場合は、Source を「Deploy from a branch」にして `main` / root を選んでも公開できます)

## 技術構成

- [Three.js](https://threejs.org/) r160(importmap 経由で CDN 読み込み)
- 単一の `index.html`(HTML / CSS / JS すべて含む、ビルドツール不使用)
- ステートマシンによるゲーム進行: `ready → charge → flying → retrieve → bite → fight → result`
- 魚のAI: 回遊 → 追尾(リトリーブ速度・深度・アクションで興味判定)→ バイト → 逃走
- ファイト: スタミナ / 走り・休みの切り替え / ラインテンションの簡易モデル
- 効果音は WebAudio によるプロシージャル生成(音声ファイルなし)、
  アタリ・ヒット時は Vibration API で振動(対応端末のみ)
